# open-jev

*[In English](README.md)*

Превращает промпт в маленький, быстрый и откалиброванный классификатор. Вы описываете решение в
YAML-файле — выбор из вариантов, оценка по рубрике или истинность утверждения, — а `openjev`
заставляет локального LLM-учителя (здесь Qwen3.8-27B на vLLM) разметить несколько тысяч примеров
*мягкими* метками (вероятности по вариантам, снятые с логпробов одного ограниченного токена-буквы),
дистиллирует их в энкодер на ~140M параметров, калибрует его на отложенной выборке и отдаёт результат
по `POST /v1/systemone`. На выходе — типизированное решение с вероятностями, по которым можно ставить
порог, а не строка, которую надо разбирать. Это открытая реализация идеи, стоящей за Jev от TypeSafe:
сам Jev — закрытый хостинговый API, его заявленные цифры снаружи проверить нельзя, поэтому здесь они
не повторяются; все числа в этом репозитории получены кодом из этого репозитория.

**Задача** (один YAML) → **учитель** (одна ограниченная буква на пример, softmax по её логпробам)
→ **ученик** (`mmBERT-small`, обучение на `KL(teacher ‖ student)`) → **калибровка** (`logits / T + b`
на выборке в 500 строк) → **сервинг** (типизированный JSON на `/v1/systemone`). Всё складывается в
`runs/<task>/`. Подробно по стадиям, точный запрос к учителю и `openjev augment`:
[`docs/pipeline.md`](docs/pipeline.md). Справочник по YAML задачи и разбор того, как завести свою:
[`docs/task-spec.md`](docs/task-spec.md).

## Быстрый старт

```bash
uv venv && uv pip install -e . && . .venv/bin/activate   # ./.venv; python -m venv .venv тоже подойдёт
cp tasks/example.yaml tasks/mytask.yaml                  # своя задача: поправьте question, options, data.source
OPENJEV_TEACHER_URL=http://localhost:8000/v1 openjev run tasks/agnews.yaml   # label -> train -> calibrate -> eval
openjev serve runs/agnews --port 8099                    # блокируется; curl — из другой оболочки
curl -s localhost:8099/v1/systemone -H 'Content-Type: application/json' \
  -d '{"model":"agnews","input":"Shares of the airline fell 8% after it cut its full-year profit forecast."}'
```

Последняя строка, выполненная против `runs/agnews`, печатает:

```json
{"model":"agnews","choice":"Business","probabilities":{"World":0.005825810134410858,
 "Sports":0.005110130645334721,"Business":0.9872164130210876,"Sci/Tech":0.0018476743716746569},
 "confidence":0.9872164130210876}
```

![openjev run tasks/agnews.yaml](docs/img/terminal.svg)

`GET /v1/models` перечисляет загруженные прогоны. Каждая обслуживаемая модель — это один обученный
ученик с фиксированным типом и фиксированным набором меток: это не универсальная модель, которой
можно передать произвольные варианты в запросе. Батчи, флаг эскалации, конформные множества
предсказаний, `openjev push` и сравнение с чужим эндпоинтом: [`docs/serving.md`](docs/serving.md).

Запускайте всё из корня репозитория (`results/` и README разрешаются относительно него). Тесты:
`pytest -q tests` — меньше минуты на CPU, без GPU и без учителя (они же гоняются на каждый push через
`.github/workflows/test.yml`); двум из них нужны `jhu-clsp/mmBERT-small` и `fancyzhx/ag_news` в кэше
Hugging Face.

Задачи здесь английские и русские, но ничего языкозависимого в коде нет: `question`, `options` и
`statement` — свободный текст, так что пишите их на том языке, на котором хотите промптить учителя,
лишь бы его понимали и учитель, и чекпойнт ученика (mmBERT многоязычный). Само поле `lang` — это
только колонка в отчёте и язык, на котором генерирует `openjev augment`.

Учитель во всех строках — **Qwen3.8-27B**, 3-битная квантизация GSQ (ISTA-DASLab) с MTP, поднятый
vLLM на этой же машине под идентификатором `Qwen/Qwen3.8-27B-FP8`, вызовы с `max_tokens: 1` и
`enable_thinking: false`. Любое число «учителя» в таблице — это та же модель zero-shot; ученик не
может обойти её иначе, чем убрав из неё шум. Прогоны до 2026-09-20 не записывают идентификатор модели
в `runs/<task>/label.json`, более поздние — записывают.

Что означает каждая колонка и чего она не означает:
[`docs/findings.md#what-the-numbers-mean`](docs/findings.md#what-the-numbers-mean).

## Что мы выяснили

Девять прогонов, один учитель, две ночи. Каждая разница ниже — парный бутстрап по общим строкам eval
(`openjev compare`, 2000 пересэмплирований); если 95 % доверительный интервал накрывает 0, это
записано как *нет измеримой разницы*, а не как выигрыш. Разбор с числами и оговорками — в
[`docs/findings.md`](docs/findings.md), таблицы и команды — в
[`docs/experiments.md`](docs/experiments.md).

- **500 золотых меток дают больше как поклассовый сдвиг при калибровке, чем как обучающий сигнал.**
  `logits / T + b`, подогнанный на калибровочной выборке из 500 строк: headlines 0.767 → **0.843**,
  kinopoisk 0.609 → **0.660**, georeview MAE 0.783 → **0.609**. Секунды на CPU, без переобучения и без
  вызовов учителя. На agnews и banking77 это не даёт ничего — там маргинал учителя и так верный.
- **Со сдвигом два ученика обходят своего учителя, а два — догоняют его.** Основная ошибка учителя на
  трудных задачах — смещённый маргинал, а K-мерный сдвиг — ровно та поправка, которая его снимает.
- **Оговорка: нужно знать свой prior.** Путь без золота (объявленный `prior:`) отстаёт меньше чем на
  полпункта — но только потому, что эти бенчмарки сбалансированы по построению.
- **Две ручки, которые, как оказалось, ни на что не влияют**, стоило измерить их с контрольной
  группой: 12 эпох против 5 и раунд `openjev augment` (PGKD-lite). И там, и там — *нет измеримой
  разницы*.
- **Бюджет — это учитель.** 66 522 вызова и 2,4 часа разметки на шести задачах; ученики обучаются за
  1,5–12 минут, а каждый пост-хок результат — это секунды CPU поверх логитов, уже лежащих на диске.
- **Каскад работает офлайн и часто не нужен.** Четыре прогона из девяти достигают паритета с учителем
  при 0 % эскалации. `serve` возвращает `"escalate": true/false` и сам учителя никогда не вызывает.

Где метод перестаёт работать — неверный prior, ошибки на уровне отдельных примеров, дрейф, `K > 19` —
[`docs/findings.md#limitations-and-follow-ups`](docs/findings.md#limitations-and-follow-ups).

## Реальные задачи

Ещё пять задач через тот же конвейер, но на входах из работы агентов: оценить прогон веб-агента по
логу действий, выбрать элемент для клика, разметить DOM-узел полем схемы. Четыре работают, одна
падает — и это полезный результат. Числа, таблицы порогов и ограничения:
[`docs/use-cases.md`](docs/use-cases.md) (на английском).

- **Вырожденный учитель всё ещё может быть полезным скорером.** В `arb-success` учитель отвечает
  *не успешно* на 99,9 % строк (в золоте успешны 26,6 %) — macro-F1 0,426, — но его вероятности
  ранжируют прогоны с AUROC 0,837. Ученик: AUROC 0,843, macro-F1 0,695, ECE 0,214 → 0,064. Однако
  точность по классу *true* — 0,56 при покрытии 80 %: это фильтр для человека, а не авто-приёмка.
- **На невиданных сайтах ученики обходят своих учителей.** `swde-field` (33 поля, 3 вызова учителя
  на строку): 0,864 acc / 0,917 macro-F1 против 0,803 / 0,876; `m2w-target` (действовать или
  спросить, по одному элементу): 0,863 acc против 0,783, AUROC 0,904, и порог отвечает на 87 %
  элементов с точностью 0,870. 6 мс на решение, 714–1054 примеров/с при батче 64.
- **`choice` — неподходящий примитив для кандидатов, своих в каждой строке, и это и есть вывод.**
  `m2w-element` («какой из этих 16 элементов») схлопывается до 0,059 accuracy при случайном уровне
  0,0625: слот `G` в каждой строке значит другое, и фиксированной голове нечего выучить. Ранжирование
  по каждому кандидату (`m2w-target`) — та же задача, и она работает.
- Слабый результат, так и записан: `arb-quality` (оптимальность 1–4) MAE 0,776 против 0,809 у
  учителя — учитель едва выше случайного, а учитель здесь потолок.

Весь трек: 35 900 вызовов учителя, 118 минут разметки, три сида там, где это имело значение
(`openjev compare` везде говорит *нет измеримой разницы* между сидами).

## Требования

- Эндпоинт vLLM (или другой OpenAI-совместимый) с поднятым учителем, доступный по
  `OPENJEV_TEACHER_URL`, с поддержкой `logprobs` + `top_logprobs` и вендорного поля vLLM
  `structured_outputs`. Разрабатывалось против Qwen3.8-27B (3-битный GSQ + MTP, алиас
  `Qwen/Qwen3.8-27B-FP8`) под vLLM на той же машине. Подойдёт любая instruct-модель, возвращающая
  логпробы букв; она же задаёт потолок качества.
- Одна NVIDIA GPU для обучения. Замеренные пики для mmBERT-small при батче 32: **5,5 ГБ при
  `max_len: 256`, 8,9 ГБ при `max_len: 512`**. Для mmBERT-base — **9,9 ГБ**, что уже не помещается
  рядом с резидентным vLLM на 84 ГБ на этой машине: один прогон так и убили, поэтому base здесь рядом
  с учителем не обучается. Для `serve`, `calibrate`, `eval` и `compare` хватает CPU.
- **Не дайте обучению уронить учителя по OOM.** На машине с унифицированной памятью тренер и vLLM
  делят один пул, и OOM-killer хоста с удовольствием прибьёт процесс на 84 ГБ. Все прогоны обучения в
  этом репозитории идут через `scripts/gpu_queue.sh`: одна задача за раз под `flock`, каждая под
  `choom -n 1000`, чтобы killer выбрал тренера, и с проверкой памяти, которая *ждёт* перед запуском
  задачи, а не урезает размер батча (другой размер батча — это уже другой эксперимент).
- Python ≥ 3.10 и зависимости из `pyproject.toml` (torch, transformers, datasets, httpx, pyyaml,
  numpy, scikit-learn, fastapi, uvicorn). Других зависимостей в рантайме нет.
- Разрабатывалось на DGX Spark (GB10, 20 ядер, 128 ГБ унифицированной памяти), Ubuntu 24.04,
  torch 2.13/cu130.
- Если выставлены `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` — снимите их: они ломают обращения к учителю
  на localhost и замедляют скачивание с Hugging Face. Сам клиент учителя ходит с `trust_env=False`.
